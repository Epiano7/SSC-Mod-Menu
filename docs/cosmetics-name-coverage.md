# Cosmetics name rendering coverage

The local Cosmetics override uses the current local account name and, where available, the native actor or chat-sender record. It does not alter the game's networked player name and is not an authorization mechanism. The October 8 shared-cosmetics candidate separately publishes an opted-in appearance to the cosmetics service for other opted-in mod clients; unmodified clients retain the game's appearance.

Shared appearances are applied only to attributed human actor, scoreboard row and chat-sender paths using the native account key. Nested text rendering preserves the scoped remote palette. Own cosmetics take priority; private bot authorization remains independent. Remote cached leaderboard/profile labels without verified account attribution are not overridden. See [shared cosmetics](shared-cosmetics.md) for enrollment, limits and validation status.

The October 3 candidate covers both common native text paths: narrow strings converted by the game and directly rendered UTF-16 strings. This includes cached list/profile/leaderboard labels that bypass the older screen-specific adapters. Solid colors, rainbow, and custom gradients use the same selection logic. Both native glyph palette paths respect the scoped custom palette.

Ownership supplied by the actor, scoreboard row or chat sender takes precedence over text matching. In shared UI paths without that ownership context, only a complete match to the current account name qualifies. Substrings and punctuation-stripped matches are not used. ASCII case normalization matches the existing account adapter; UTF-8 account names are converted to UTF-16 with invalid encodings rejected. A text-only label cannot distinguish two accounts with identical labels; attributed actor/sender paths retain their explicit non-local decision.

The source call list is a compatibility-checked rendering list, not a list of approved accounts. The current executable has 70 direct edges to the shared single-line and wrapped text routines: 67 are routed through the adapters. Chat input, chat message bodies, and quick-wheel message bodies retain their existing rendering. Formatted chat sender labels are covered separately using the sender record. Both narrow-to-wide conversion edges and all four glyph palette calls are checked. Full native function fingerprints guard these call sites; no unvalidated runtime scan patches arbitrary text.

Adapters inspect MSVC string storage before forwarding. Inline and heap UTF-16 strings are handled separately, reads are bounded and checked, native string ownership is preserved, and all layout, alpha, clipping and shadow arguments pass through unchanged. Decisions are scoped and restored around each draw, with no persisted identity match.

Validation: warnings-as-errors build, isolated name adapter/ownership/string tests, menu and hotkey tests, a complete shared-text call-edge audit against the current executable, and native compatibility checks. Live checks should include the ranked leaderboard row, account header, own chat sender, friend/recent-player or profile lists, scoreboard and overhead labels. Test solid, rainbow and two/three-color gradients, switch Cosmetics off, and confirm other players retain their colors. Windows and Proton visual checks must be recorded separately; static coverage does not establish that every screen has been visually tested.
